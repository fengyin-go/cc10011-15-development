# 采集调度策略管理工具

离线版采集调度策略配置工具，涵盖站点登记、模板编排、代理轮换、限速调节、反爬策略、增量水位与结果校验规则，所有配置持久化到浏览器本地存储。

这是一个**纯前端**管理平台：React + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 React + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面（含重试编排页 retryorch/）
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/api/retry-orchestration-service.ts   重试编排：分类归并、幂等批次、冲突判定、恢复回写
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化（含重试编排状态）
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 重试编排（失败采集记录幂等重试）

失败采集记录不再只保留失败状态：重试编排页（导航「重试编排」）读取失败采集结果、重试机制里
已启用策略的可重试异常与最大重试次数，把失败记录分类归并成**幂等重试批次**，供采集作业按计划继续。

- **幂等约束**：同一失败记录重复进入分类只占一个重试位置，重复触发不会生成第二个批次；
  达到最大重试次数后仍保留最后一次错误；重试批次与原失败记录一起保存，不可重试证据不丢。
- **双重归并**：按错误类别与按采集作业两种归并记录同时落库；恢复时先核对按错误类别归并重试记录，
  复核依据也是它。
- **冲突判定**：同一地址同时出现网络错误、认证错误等多类错误时，两种归并方式会形成不同批次内容与
  后续等待计划，需值班员判定其一；判定后批次自动调整并留存核对记录。
- **恢复与回写**：任务编排恢复只恢复可重试记录，不可重试错误进入待人工处理区；恢复成功的采集作业
  回写为待执行，待处理区同步更新；批次保留上一份确认记录与本日数据凭据。
- **人工区与重新分类**：不可重试记录在待人工处理区单独保留；值班员可重新分类失败记录，
  重试机制用户可在核对记录里复核。
- **导出与打包**：失败清单可导出 CSV 下载；修复后可再次提交同一批次（不生成新批次）；
  发布前可将批次打包为 JSON 下载。
- 编排数据持久化在 localStorage 的 `scraper-strategy-studio:retry-orchestration`，
  页面上「重置编排数据」可回到示例状态。
- 冒烟测试（Node 直接跑服务层全流程）：`cd frontend && npm run test:orch`

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `scraper-strategy-studio:entries` 这一项，或调用 `resetModule(模块)`。
